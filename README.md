# СПОТ

Мобильное приложение — личная карта мест, куда хочется попасть.

Стартовый рынок: Москва и Санкт-Петербург.

## Продукт
СПОТ позволяет:
- сохранять рестораны, кофейни, бары, отели и другие места;
- видеть сохранённые места на карте;
- находить свои споты рядом;
- открывать «Для тебя» — новые места рядом с текущей областью карты, ранжированные по выбранным интересам, категориям уже сохранённых мест, рейтингу, отзывам и расстоянию;
- собирать коллекции;
- автоматически собирать маршрут на 3–5 остановок из сохранённых мест с учётом любимых категорий, рейтинга, часов работы и расстояния;
- строить маршрут пешком или на машине, опционально начиная с текущей геопозиции только после явного нажатия пользователя;
- планировать маршрут не только «сейчас», но и на вечер или следующий день — часы работы проверяются к ожидаемому времени прибытия;
- запускать сохранённый маршрут в режиме «по ходу»: видеть текущую и следующую точку, открывать навигацию до текущей, отмечать место посещённым или временно пропускать его;
- считать реальные длины и время участков через 2ГИС Routing API, а при недоступности routing-доступа или сети безопасно переходить на локальную оценку;
- сохранять пользовательский порядок мест в подборках, включая публичные ссылки;
- сохранять с маршрутом его настройки — транспорт, время старта, длительность остановки и способ старта — повторно открывать маршрут из подборки и менять эти настройки позже;
- делиться подборками по публичной browser-ссылке без обязательной установки приложения;
- отмечать посещённые места;
- переносить гостевой профиль на другое устройство одноразовым 10-минутным кодом;
- делиться одним сохранённым местом через приватную share-ссылку без передачи заметок и исходного источника;
- принимать ссылки через системное меню «Поделиться → СПОТ» на iOS и Android;
- сохранять источник места и дальше развивать автоматическое определение через resolver/AI.

## Структура
- apps/mobile — React Native / Expo приложение
- services/api — Go API
- database/migrations — PostgreSQL + PostGIS
- packages — общие пакеты
- infra — инфраструктура и deploy

## Локальный запуск
1. Скопировать .env.example в .env
2. Запустить docker compose up -d
3. В apps/mobile выполнить npm install и npm start
4. В services/api выполнить go run ./cmd/api

## Share Extension / системное «Поделиться»
Для нативного приёма ссылок нужен development/production build — Expo Go не содержит нативный share-модуль.

1. `cd apps/mobile && npm install`
2. `npx expo prebuild --clean`
3. `npx expo run:ios` или `npx expo run:android`
4. В браузере, 2ГИС, Instagram, TikTok или Telegram открыть «Поделиться» → «СПОТ».

В Expo Go остальная часть приложения продолжает работать, share intent там автоматически отключён.


## Миграции базы данных
Все миграции лежат в `database/migrations`, а production-safe копия полного набора также встраивается в Go API. Поэтому API умеет поднять **пустую PostgreSQL/PostGIS базу с нуля** без ручного SQL и дальше последовательно обновлять существующую схему.

При старте API с настроенным `DATABASE_URL` миграции выполняются автоматически под PostgreSQL advisory lock и записываются в `schema_migrations`. Bootstrap-миграция идемпотентна, seed-данные Москвы/Петербурга и категорий обновляются через `ON CONFLICT`, а API не начинает принимать трафик, если обязательная миграция не применилась.


## Apple / Google identity foundation
API умеет криптографически проверять OIDC ID token от Google и Sign in with Apple по официальным JWKS, проверяет issuer, audience, срок действия, RSA-подпись и nonce (когда он передан клиентом).

Провайдер включается только после настройки допустимых audience:
- `GOOGLE_CLIENT_IDS` — один или несколько client ID через запятую;
- `APPLE_CLIENT_IDS` — один или несколько Apple client/service ID через запятую.

Первое подключение делается к уже существующему гостевому профилю через `/api/v1/me/identity/link`, поэтому сохранённые споты и подборки остаются у того же пользователя. После этого `/api/v1/auth/provider` может открыть тот же профиль на другом устройстве.


## Маршруты
Мобильный планировщик собирает последовательность только из личных сохранённых спотов со статусом «Хочу»/«Бронь». При ранжировании учитываются интересы, избранное, рейтинг, разнообразие категорий, географическая компактность и состояние заведения к предполагаемому времени прибытия. Пользователь может планировать на текущее время, ближайший вечер (19:00) или следующий день (12:00), выбрать 30/45/60 минут на каждой точке и вручную переставить остановки. После ручной перестановки расстояние, время в пути и ожидаемое время прибытия пересчитываются под новый порядок.

Для участков между точками API использует тот же `TWO_GIS_API_KEY` и Routing API 2ГИС. Несколько последовательных участков отправляются одним batch-запросом; результаты кэшируются в памяти API (15 минут для пеших/велосипедных маршрутов и 2 минуты для автомобильных), чтобы повторные перестроения не умножали запросы к провайдеру. Если routing-доступ не включён для ключа или провайдер временно недоступен, маршрут остаётся рабочим и получает оценочные расстояние/время по координатам.

Кнопка «От меня» запрашивает foreground-геопозицию только после явного действия пользователя и не включается автоматически. Для передачи готового маршрута в пошаговую навигацию используется универсальная Google Maps Directions URL без отдельного API-ключа.

Сохранённый маршрут можно запустить прямо из подборки. Режим прохождения автоматически берёт первой ещё не посещённую точку, показывает следующую, открывает навигацию только до текущей точки и позволяет отметить её посещённой. Отметка «посещено» использует обычный статус спота и поэтому сохраняется/синхронизируется существующим облачным механизмом; временное «пропустить» действует только в текущем запуске маршрута и не меняет данные пользователя.

Сохранённый маршрут становится специальной route-подборкой. В cloud snapshot и нормализованной библиотеке сохраняются только настройки маршрута (`transport`, `start_preset`, `stop_minutes`, `start_mode`) и порядок `placeIds`; точная геопозиция пользователя не сохраняется. Для PostgreSQL это поле хранится в `collections.route_plan` (JSONB). Из карточки сохранённого маршрута пользователь может позже поменять транспорт, время старта, длительность остановки и режим старта; изменения синхронизируются как обычная часть коллекции. Если маршрут был создан «от меня», при повторном открытии карты снова используют текущее местоположение устройства. Публичная browser-ссылка также показывает, что это маршрут, и умеет открыть всю последовательность точек одной ссылкой.

## Персональные рекомендации
«Для тебя» запускается только по явному нажатию пользователя и не требует геолокации: центром поиска служит текущая область карты. СПОТ выбирает до двух приоритетных категорий из onboarding-интересов и истории сохранённых спотов, делает по одному обычному Places-запросу на категорию, исключает уже сохранённые места и ранжирует новые результаты по совпадению с интересами, рейтингу, количеству отзывов и расстоянию до центра карты. Запросы используют существующий кэш/singleflight Places API, поэтому функция не создаёт отдельный поток нагрузки на провайдера.

## Нагрузка и защита Places API
Поиск мест кэшируется внутри каждого экземпляра Go API на 2 минуты в ограниченном TTL-кэше. Координатный поиск группируется примерно по 100-метровым ячейкам, а одинаковые одновременные запросы объединяются через singleflight, чтобы всплеск клиентов не превращался в такой же всплеск запросов к 2ГИС.

HTTP-сервер использует ограничения времени чтения/записи и корректно завершает активные запросы при SIGTERM/SIGINT. Это позволяет безопаснее масштабировать API несколькими репликами за балансировщиком и обновлять их без резкого обрыва трафика.


## Публичные ссылки на места
СПОТ создаёт публичную ссылку на место только после явного действия пользователя «Поделиться местом». Ссылка использует отдельный случайный токен `ps_...`, а не внутренний ID пользователя или записи. В публичный ответ попадает только общая информация о месте: название, категория, город, адрес, координаты, рейтинг, часы и описание. Личные заметки, статус, избранное, дата сохранения и исходная ссылка пользователя не публикуются.


## Распознавание ссылок из соцсетей
При импорте публичной ссылки Instagram, TikTok или Telegram API сначала пытается прочитать только публичные HTML-метаданные страницы (Open Graph / title / description), очистить служебный текст платформы и использовать найденный контекст для поиска места в Москве и Санкт-Петербурге.

Fetch разрешён только для поддерживаемых доменов соцсетей, ограничен по времени, размеру ответа и редиректам. Если платформа не отдаёт публичные метаданные или совпадение получается неуверенным, СПОТ не делает вид, что «угадал»: пользователь видит найденные кандидаты либо уточняет название вручную. Исходная ссылка при сохранении остаётся привязана к споту. Если страница отдаёт заголовок или фрагмент подписи, СПОТ также сохраняет этот публичный контекст в личной карточке места, чтобы спустя месяцы было понятно, почему место попало в карту. Эти поля синхронизируются внутри личного cloud snapshot и дополнительно проецируются в приватную нормализованную библиотеку `user_places`, чтобы серверный поиск/история в будущем не зависели от snapshot-формата. В публичную ссылку на место source memory не входит.
